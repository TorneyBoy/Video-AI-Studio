## 数据与事务约束

`0010_edit_revisions`新增edit_documents、plan_revisions、timeline_revisions和edit_heads；不改写M1历史Job、费用或媒体文件。原计划Worker在同一完成事务中初始化第一版；对既有已完成计划可通过正常业务接口延迟建立编辑文档。旧计划缺少历史分析快照时，保存的是建立文档当时的候选依据，实际源区间以已编译时间线为准，不伪称恢复了从未保存的历史分析。新计划在入队时保存模板，分析完成编译时再固定来源及计划。

版本API只追加，不提供原地更新或删除版本。读取、编辑、渲染会检查存储的内容哈希。已有版本对应的Timeline和包含编辑历史的项目不能通过普通删除入口移除，返回明确业务错误；生命周期清理与项目归档由后续任务补齐。

初始化的锁顺序是原Job再到新文档/head；保存现有文档只锁head，不反向获取Job或预算锁。渲染只读明确快照，再使用原有任务/预算事务。真实PostgreSQL专项检查两页竞争、同请求竞争及保存期间渲染，不能用SQLite顺序测试代替并发证据。

同一版本的来源素材必须仍属于当前空间/项目，URI、类型和对象SHA-256与快照一致。改名和标签不会改动这些字段；重新分析不会覆盖旧版本的候选。新增生产视频候选须先有已核验对象与有效镜头分析。规划分析与ASR正文分开保存：当前新版本在独立transcript/1快照固定原文，字幕修订另存时间线；早期版本未保存的原文只能由明确导入读取当时已有分析，不能伪称是历史原文。候选池最多20,000镜头，来源及原文快照最多16MiB；候选接口有分页。

版本和输出规格参与逻辑请求指纹；重试次数属于首次任务的执行预算，重复提交不会暗中增减它，也不会因客户端再次带上默认值而另建付费任务。手工Timeline的数据库记录ID与Canonical Timeline内部ID可能不同，旧入口保留这一兼容性；新版本的引用则由服务端成对建立。

已执行的专项包括`tests/test_edit_revisions.py`、`tests/test_postgres_editing.py`、既有产品/P0流程、计划与迁移，共32项通过。覆盖冻结模板/分析、锁定与局部重算、旧表单冲突、丢失确认查询、重复请求、恢复/连续撤销、源变更与哈希损坏、必需槽位不足阻止渲染、Worker提交前复核和服务端产物绑定。PostgreSQL另覆盖同版竞争、同请求竞争、编辑期间渲染，以及并发不同参数复用同一计划键。证据为`data/testing/m2-versions/revision-contract.log`。原生共享DTO已新增并通过TS检查，但没有据此声称微信页面可用。

版本后端基础批次的自动质量门为 **381 passed、1 skipped，ALL: PASS**，见`data/testing/m2-versions/quality-gate.log`；不是后续页面批次的测试数。手工时间线两种ID的兼容和默认重试参数问题已修复，版本/输出冲突规则未放宽。最新页面及帧精度结果见下文。

## C08 片段基础批次（后续实现）

新增动作仍调用同一个条件保存接口、操作键和恢复收据；未增加任意客户端时间线覆盖入口。`editor`只读视图提供实际fps、时长、分辨率、轨道和片段参数，不复制媒体URI、元数据、授权地址或字体位置。网页显示轨道片段条及上下文输入；小程序显示横向片段条及精确输入面板。UI的“镜头数”在分割后代表片段数，同一来源镜头的不同部分可单独编辑。

| 动作 | 输入与实现 | 效果与边界 |
| --- | --- | --- |
| trim_clip | clip_id、source_start/source_end绝对源秒数；限制在冻结分析镜头范围，起点向内上取整、终点向内下取整 | 裁切后主视频顺接，总时长跟随变化；不变速、不读取镜头外内容 |
| split_clip | clip_id、offset_seconds从当前片段开头算起；向下对齐完整帧，两边至少一帧 | 左片段保留ID，右片段ID由版本与原操作确定；源区间首尾连续，输出总帧数不变；重复原请求不增加分割 |
| move_clip | clip_id、to_index为当前主轨0起始序号 | 片段移动并重新顺接，源区间、音量和其他参数保留 |
| remove_clip | clip_id；至少保留一个主视频片段 | 删除并顺接，不修改旧版本；必需槽位按不同来源镜头重新计算，缺失时渲染前拒绝。分割同一镜头不能伪造满足多个必选来源 |
| set_clip_audio | clip_id、volume为0–4倍（0静音、1原音） | 视频/现有音频片段的原声音量进入新快照，重排/恢复保留；不是独立配乐、淡入淡出或音质验收 |

每个动作会检查锁定片段的内容与位置是否被改变。锁定后方片段时，缩短前方片段会被拒绝；总时长不变、未改锁定片段的前方分割可以保存。恢复仍追加新版本。逐片裁切后的整体时长设置只在当前裁切区间内分配，不恢复被用户剪掉的内容，也不重置音量；超出可用总时长只保留当前区间并提示。

本批顺接操作针对一条连续且按帧对齐的主视频轨；含空隙、重叠、转场、自定义效果或隐式变速的旧时间线明确拒绝这些操作，不悄悄丢掉原效果。其他音频/叠加/字幕轨保留绝对时间点，超出新时长时拒绝保存，保留原内容；存在这些轨道时提示审阅同步。后续需补齐叠加/转场、各轨精确区间、字幕/音频编排及真实输出，不能据此标记C08/C09完成。

双端对同一片段只保留当前动作组的原始输入，切换动作需先保存/放弃，避免裁切草稿被其他参数覆盖。网络结果未知时保留原提交；409保留原参数，刷新不自动改写base或重新提交。单版本最多10000个片段，服务端各动作仍受原100操作/请求限制。

## 音轨、叠加和转场命令

`save_audio_clip`和`save_overlay_clip`共享`clip_id`（新增为null）、`track_id`、`asset_id`、成片`start/end`和`source_start`。只引用当前版本捕获的素材，`source_asset_ids`可随本次保存明确加入本项目素材；返回`editor.sources`仅有id/名称/类型/有声标记，不返回URI或授权。更改同类型轨道名称会移动原片段，稳定ID保持不变；不能跨音频/叠加类型隐式转换。

音轨增量为`volume`（0–4）、`fade_in/fade_out`（秒）和`role`（voice/music/other）。淡入淡出向内对齐帧、合计不超过片段；保存为`audio-envelope/1`效果。叠加增量为画布内`placement{x,y,width,height}`、`opacity`和`fit`（contain/cover/stretch），保存`frame-fit/1`；图片按指定输出区间停留，素材起点须0；视频源区间必须足长。叠加音量固定0，音频另行明确添加。

`delete_layer_clip`仅删音轨/叠加片段，`delete_layer_track`仅删此两类轨道。`set_track_mute`的主视频语义是静音原声，字幕/叠加语义是隐藏；锁定镜头仍受保护。`move_track`仅调整非主视频轨且不占首位，更新叠加/字幕层级。同轨区间不能重叠，多轨混合仅记录明确编辑意图，实际执行仍需对应服务验收。

`set_video_fit`为主视频选择contain/cover/stretch。`set_transition`为片段设置入场类型和时长，none清除转场。`composition/1`规则要求相邻输出区间重叠该时长，输出时长等于源区间总长减转场重叠，不冻结或补齐末帧。转场短于相邻两段，不允许三段同时叠加；分割仅左半保留原入场转场。固定轨道越界、随源字幕映射不连续或同轨字幕重叠时拒绝，原版本保持不变。

`editor.advanced_support`返回当前版本的无网络准入结果及缺失效果。新建任务/预算预占前，以及首次提交供应商前，必须由同一个可用服务覆盖全部效果；保留既有收据和已知远程作业核对。此检查不主动调用健康探测或媒体服务。当前云配置仍为M1受限子集，新增音轨/叠加/转场和未验证字体不开放真实执行。编辑、元数据验证与文本导出不能替代真实媒体效果验收。

## 成片审核绑定与交付

`GET /artifacts/{id}/review`返回安全的当前绑定摘要、结构质检测量、最近决定、版号、意见和可播放/可正式领取状态。`POST /artifacts/{id}/reviews`使用Idempotency-Key，body为binding_hash、base_review_id、decision（approved/changes_requested）、note与issues。每条问题含category、severity、message及可选成片start/end；时间在该成片时长内，退回必须说明，提交的错误级问题不能和批准同时保存。审核人来自已认证身份，当前个人所有者可自行审核；编辑者只读这些决定。

`GET /artifacts/{id}/review-requests/{key}`核对原回执，返回原决定和当前状态，不执行修改；`GET /artifacts/{id}/reviews?skip=&limit=`分页读历史。旧请求重放不会把后来的决定回退，竞争决定使用CAS，真实PostgreSQL检查已覆盖。同一份渲染输出单独审核，另一份Draft/Final或新版本的产物不会继承。

绑定包括归档字节哈希/大小、结构QC指纹、输入manifest和计划/时间线版本。批准前核对manifest与QC、来源快照及输出版本身份。下载授权前后均重查审核和归档/任务状态，期间退回或更换批准记录不会返回这次下载地址。预览仍可用于审阅，既有短期URL按TTL失效，不能承诺收回已经保存的媒体。原生播放/下载URL和临时文件路径不进入审核草稿。

此变更也适用于新代码部署后的原始manifest成片：没有编辑版本的旧输出仍可按其实际manifest和归档内容审核，不自动伪造旧批准。M1生产尚未升级，不能把本机演练当作线上交付策略已切换。更完整的机器质检和真机交付仍在完整M2范围内。
