# M2 统一账号与个人空间

当前为实现中的身份基础，**账号边界、旧库升级和真实PostgreSQL刷新竞争自动检查已通过，尚未完成M2整阶段验收或部署**。本机网页已实测注册进入真实个人空间。服务器仍使用已验收的 M1 control v8 / gateway v11 和 SSH 私有入口。不得把这些检查视为微信登录、双端一致性或公开上线已经通过。

## 身份与空间

用户、个人 Tenant、Membership 分别持久化。新注册用户在同一个事务内建立个人空间、owner 关系及默认开启但额度为零的阻断预算。用户提交的 Tenant ID、OpenID、UnionID 或本地缓存不能决定登录身份。旧 M1 Tenant 不自动归属某个新用户，后续迁移需要核实归属并单独记录。

现提供[隔离库中的旧空间个人账号准备](legacy-personal-adoption.md)：指定空间/slug/数据库实例后，由受控运维CLI新建账号和owner关系，原业务Tenant及预算保留。没有客户端认领接口，不合并既有账号、角色或空间；0021只建审计表，不自动分配真实用户。微信平台登录仍未接通，账号密码的mini令牌检查不代表微信/真机验收。

`AUTH_MODE=session` 是新增账号边界；既有 development_header 仅用于开发，trusted_proxy 保留给受控的 M1 私有部署。session 模式拒绝客户端租户头与签名代理头，每次从服务端会话和有效成员关系解析空间，普通账号仍不能调用租户管理或内部完成接口。当前仅 owner/editor 可取得业务会话；成员协作与只读角色在 F03 补齐，不声称已具备完整 RBAC。

## 会话实现

密码使用 stdlib scrypt，N=2^17、r=8、p=1、独立16字节盐；限制同时进行的密码计算，避免并发请求占满控制面内存。账号按小写字母、数字、下划线归一化；密码15至128字符，允许长口令。密码和错误请求中的 token 不写日志、审计或校验错误响应。[密码存储依据](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

访问令牌和刷新令牌分别包含256位安全随机数，数据库只保存SHA-256摘要。访问期默认15分钟、刷新绝对期7天；刷新原子消费旧令牌并替换访问令牌，旧刷新令牌重放会撤销整条会话。退出、单设备撤销、密码变更和成员停用均使服务端会话失效；密码变更撤销所有旧设备并建立新的当前会话。[会话管理依据](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)

网页只使用 HttpOnly、SameSite=Strict、生产 Secure 的主机Cookie，生产名称带 `__Host-`，不设置Domain、Path=/。不会把密码或Bearer写入localStorage。所有Cookie写操作检查明确的同源Origin；网页登录/注册/刷新同样检查来源。小程序使用JSON返回的Bearer与轮换刷新令牌，不混用Cookie；两种传输同时出现则拒绝。多标签页刷新使用同源Web Locks串行并在刷新前重新查询会话；缺少该能力的浏览器只有页内合并，跨标签页冲突可能要求重新登录，M2阶段需实际验证兼容范围。

登录、注册、刷新和改密设持久化速率上限；限流键只存摘要，失败后的回滚不释放已用尝试。认证响应及session模式业务API禁止缓存。部署时需让TLS代理覆盖客户端转发头，只信任固定代理来源；不能用外部传来的IP字段决定限流身份。

## API与页面

| 动作 | 入口 | 结果 |
| --- | --- | --- |
| 查询接通状态 | GET /api/v1/auth/capabilities | 当前登录、注册及微信状态，未接通能力不显示为可用 |
| 注册 / 登录 | POST /auth/register、/auth/login | 同一账号共享个人空间；web只写Cookie，mini返回令牌 |
| 恢复 / 退出 | POST /auth/refresh、/auth/logout | 轮换恢复或撤销；访问令牌过期仍可用刷新凭据退出 |
| 当前账号 | GET /auth/me | 显示名称、个人空间、有效成员关系；不返回密码或OpenID |
| 设备与改密 | GET /auth/sessions、POST /auth/sessions/{id}/revoke、POST /auth/password | 仅操作本账号会话，记录无密钥审计事件 |
| 网页入口 | /login | 注册/登录、当前账号与退出；保留现有工作台制作入口 |

表内简写 /auth 均位于 /api/v1 下。网页只在明确401后恢复会话，并复用原请求体和幂等键；网络中断或提交结果未知时不自动重复POST。切换账号清理项目缓存，跨标签页观察个人空间缓存所有者变化并重新加载。完整网页模块重组、个人资料入口和设备管理界面属于 C04 后续工作。

## 微信与外部依赖

已询问用户小程序 AppID 和 AppSecret 配置位置，不要求在聊天中粘贴密钥。官方微信开发者文档在本次浏览器被安全策略阻止，未绕过；尚未取得可核对的接口资料与配置。当前 capabilities 明确返回 wechat_login=false，未编写接收客户端OpenID冒充登录的临时接口。

后续适配只接受短期登录code，由服务器向微信兑换身份；AppSecret和session_key不进入任何前端包。显式绑定需验证当前账号和微信身份，已绑定其他用户时拒绝，不按UnionID/同名/手机号自动合并。ExternalIdentity表仅为该后续流程准备结构，尚无已接通或已验收声明。账号密码通道的独立开发继续。

## 迁移与集中验收

新增 `0008_personal_identity`，只创建身份表，不改旧Tenant、Job或财务记录。当前只准备本地迁移，不对M1服务器执行。升级前备份、单进程迁移，M2阶段末检查旧库保留、唯一约束、实际PostgreSQL刷新竞争和角色撤销；不在实现过程中逐项运行测试。

`tests/test_personal_identity.py`、`tests/test_postgres_identity.py`和旧库升级用例已纳入当前353项通过的自动质量门；本机网页注册、创建项目和素材操作已实测。M2末仍需完整网页登录/刷新/退出、多标签页与账号切换验收，以及小程序独立登录和iOS/Android真机。用户已要求微信开发工具可用后再安排，不占用该工具。密码找回、微信显式绑定、统一接口清单和双端工程尚未完成，C01–C03仍为进行中。

公开部署不复用M1固定身份代理。正式用户入口、域名/TLS迁移、全局供应商额度及账单对账就绪前保持M1私有部署；新用户默认零预算不能代替平台总费用控制。M1计费生成配额和USD10累计预算不因M2代码开发而重置。
