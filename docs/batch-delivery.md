# 固定轮次批量审核与交付（D04）

当前已接入后端、媒体网关、网页和原生小程序源码，以及离线文件/客户端与真实PostgreSQL并发检查。本机网页完成元数据样本操作和JSON导出。云上真实ZIP、真实媒体内容审核、微信平台及设备保存尚未验收，D04与M2仍未关闭；生产仍使用M1版本。

## 操作与呈现

| 子内容 | 实现 | 页面及实际效果 |
| --- | --- | --- |
| 本轮作品 | BatchRunItem固定原Job、编辑版本和输出；复用作品中心状态计算 | 网页列表、手机任务卡，展示名称/版本、审核或失败原因。筛选全部、待处理、待审核、已批准、处理中，不把失败项隐藏成整批成功 |
| 明确审核 | 选择后先获取每份输出的binding_hash和base_review_id；全部归属验证通过后，有序锁Artifact，逐项保存点执行原审核服务 | 预先显示可审核数量及旧意见，明确批准或退回。退回需意见；状态竞争项跳过，其他项提交，组回执固定保存 |
| 清单 | 从明确选择的原输出重新核对批准、来源和归档；生成确定性UTF-8 JSON和SHA-256 | 显示纳入/排除数量、原因和视频字节；每项有版本、输出哈希、大小及批准引用。导出文件与预览逐字一致，不含对象地址、源素材、凭据或短期URL |
| ZIP任务 | 固定文件集合、清单及可用字幕，创建delivery.package Job。媒体网关流式读既有归档并构建真实ZIP，控制面只协调元数据 | 任务列表显示排队、打包、失败/取消、完成；保留原任务入口。打包不触发渲染，不创建新的AI费用预占，存储读取/写入/下载仍可能计费 |
| 网页领取 | 逐项申请最新成片授权，或核对并领取完成包；临时URL不入缓存 | 逐项显示已发起和未完成数量，实际保存以浏览器为准；清单可单独导出 |
| 手机独立交付 | 新增batch-delivery原生页；wx.downloadFile不携平台身份头，检查长度/SHA后再保存相册或导出ZIP | 相册成功回调才计数，部分失败单列；ZIP交给平台文件导出，平台不支持时提示逐项保存或主动复制新签发的临时链接。不是后台持续保存承诺 |

批准只适用于具体归档字节、结构质检及原输入版本。后续另存编辑版本不会自动替换旧轮次输出；媒体/来源证据或批准改变后，旧包必须重新核对。结构质检通过不能替代人工检查画面、声音与字幕。

## 请求、重复和恢复

两端在发送审核/打包前，按账号、空间、项目保存第一方请求键、原正文及batch/run。未知结果先查询原回执；继续使用原键和正文。第一次明确4xx可结束该次新提交，未知后的403不证明原操作未执行，不清除原记录。隐藏或切换账号/项目后，迟到结果不能确认旧操作或覆盖当前页面。制作、报价、批次、原任务和批量交付页面互相阻止尚未确认期间的新写入。

组审核以tenant+key保存不可变逐项回执；同键不同正文/操作者冲突。同清单的不同创建键复用仍有效的排队/执行/成功包，以及仍可恢复的失败原任务，各自保存创建回执。取消、过期或耗尽尝试后，远端仍未知的同清单禁止另建。协调器继续核对原ID；不可恢复的任务发送取消标记，即使原POST迟到也不能重新构建。取消不表示已退费或远端立即停止。

## 接口

均位于`/api/v1/batches/{batch}/runs/{run}`，要求已认证的空间访问，响应`Cache-Control: no-store`。

| 方法及路径 | 用途 |
| --- | --- |
| GET `/delivery?state=all` | 固定轮次作品、状态计数、打包配置 |
| POST `/review-prepare` | 明确所选keys，获取当前精确审核报告 |
| POST `/reviews` | Idempotency-Key，逐项key/artifact_id/ReviewSubmit，返回部分结果回执 |
| GET `/review-requests/{key}` | 查询原组审核回执 |
| POST `/delivery-preview` | keys、include_subtitles，返回公开清单、文件校验和及限制原因 |
| POST `/packages` | Idempotency-Key，加已核对的manifest_hash；返回package_id/job_id及new或reused |
| GET `/package-requests/{key}` | 查询原包创建回执 |
| GET `/packages?skip=0&limit=20` | 包列表及分页，列表尚需领取时再次验证 |
| GET `/packages/{id}` | 重查当前批准、归档、保留期限及包状态 |
| POST `/packages/{id}/access` | 签名前后均重查后返回短期下载授权；不会将签名地址持久化 |

## 真实文件与运行边界

应用与网关的打包开关默认均关闭。每次最多100视频/300文件，默认视频合计100MiB，清单加字幕最多512KiB，网关入站正文最多2MiB；多项审核前的完整版本元数据上限16MiB。包最多保留至创建后一天，且不超过所含归档期限；这是领取授权期限，不代表云对象已配置自动删除。

网关只接受同租户`artifacts/{id}/output`归档，拒绝任意URL/跨租户路径。HEAD及条件读取后流式检查每文件长度/SHA，固定安全文件名、ZIP_STORED和时间戳，写入manifest.json及实际SRT/VTT。没有字幕则明确说明，不伪造空字幕。输出写入私有`tenants/{tenant}/packages/{id}/bundle.zip`，验证已存在对象后才可恢复同ID成功结果，控制面验证对象命名空间、大小、SHA及有效HMAC证明。

网关持久配额默认6个不同包ID，同ID重放不再扣次；单ID最多3次可恢复构建，同一网关最多1个活动构建租约，IO受240秒和取消围栏约束。控制面同一原ID最多240次/20分钟查询，等待不消耗失败尝试次数，真实失败轮次仍受Job上限约束；取消或迟到结果不能发布给已终止的Job。未知远端继续占D03容量，可信终态才释放。

先迁移0018，再同步部署API及全部Worker；网关需包含package_jobs及OSS流式实现。配置见`.env.example`、`.env.gateway.example`，临时文件目录位于独立网关数据卷。云上开关启用及配额变动另按实际剩余测试费用安排，不重置M1分析/渲染计数，不新增云角色或长期凭据。
