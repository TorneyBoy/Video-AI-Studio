## 完整目标与范围

在当前仓库代码基础上，完成面向电商商家、个人短视频创作者、代运营及批量生产用户的网页与微信小程序工作台，直到约定能力取得真实集成、双端验收和生产交付证据。

保留 **A–H 共 59 项任务、M0–M5 六个里程碑**：A01–A09、B01–B06、C01–C12、D01–D05、E01–E07、F01–F05、G01–G09、H01–H06。参考项目用于改进实现方法，不替代原任务，也不缩减目标。下面的 R01–R12 是这些任务的执行批次索引，不是额外新增的 12 项任务，不改变任务计数和里程碑关闭条件。

小程序采用原生 TypeScript，是可独立使用的个人工作台。网页所有用户能力均须在手机具备完整操作：登录、素材、策划、制作、精细编辑、批量、AI 工具、审核、费用、保存及分享。两端共享身份、项目、素材、分镜、时间线版本、任务和账务；手机可用分步页面、片段卡片和精确参数代替桌面拖放，不把高级操作强制交给电脑。平台运维、供应商密钥及后台管理不属于个人工作台功能。

## 新的执行顺序

当前以[六个执行包](development-roadmap.md#下一轮工作与验收)组织：场景规范与质量基线、多模型执行基础、真实分析与语义规划、稳定渲染与声音、受约束生成与场景选模、局部修改与双端完整验收。前两包并行，再并行推进分析和渲染声音，随后完成生成/选模与双端收口。R01中影响新链路的可靠性增量随对应包落实，R12的样本、质量、费用和环境准备全程贯穿；下列R01–R12继续作为原任务和阶段验收索引，不要求机械串行。

首批目标为商品展示、口播讲解各5组真实项目，每组5–10段素材、30–60秒成片，可包含选定补镜头、字幕与声音，并能局部修改。固定制作要求、素材和人工参考，保留未参与调参的新素材复验；记录质量、采用情况、人工修改次数/耗时及每条合格成片实际费用。首批目标不替代最终30个核心样本、M2双端各10项批次或完整M3验收。

同一业务支持多个模型和供应商适配，首批选定同类任务至少两种合格模型，提供自动/指定选择、独立参数schema和模型专属提示词版本。自动选模在报价前完成，冻结模型、场景、提示词、输入、有效参数和价格；已执行任务不静默换模，未知结果继续查询原ID。提示词离线优化须同时通过基准集和独立新素材验证，场景质量排名以真实评测为据。

## 参考项目和生产边界

- 生产固定 `PROVIDER_MODE=api_only`、`ASSET_STORAGE_MODE=external`，不自备或租用 GPU。分析、推理、转码和渲染由外部托管服务承担；控制面保存身份、元数据、版本、任务、预算和审计。自建远端 GPU 接口不因使用 HTTP 就自动符合既定托管约束。
- 参考项目用于流程、动作模型、编译方法和服务契约；不把上游整套应用、推理依赖或媒体字节塞入控制面。网关适配供应商协议、对象访问和结果证明，控制面保留持久幂等、执行代次、统一完成及账务规则。
- 采用前固定仓库提交、代码许可、具体模型/附属权重许可、服务条款及验收状态。star、演示、README 指标、接口或公开下载不证明商用资格、生产质量或已接通；许可不明不得标为可商业执行。
- **Hyperframes 按 Apache-2.0 参考；Hypit 是另一个采用自定义许可的项目，SaaS 用途需要相应授权。** 不混用名称、许可证和商用结论。其他项目的版本限制以[参考方案](open-source-reference-plan.md)及采用时重新核对的结果为准。
- 真实任务先冻结输入、版本、能力和报价；结果未知时查原任务并保留远端身份/预占，不自动换供应商重做。恢复与重新付费生成有不同语义。原素材、执行快照、审核和费用证据不可覆盖；正式交付依赖真实媒体、质量、有效授权与精确版本审核。
