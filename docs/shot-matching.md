# 镜头素材匹配、来源版本与补拍

本批推进 M3 / E03，仍是部分交付：双端已接入素材内容标注、候选比较、明确采用、来源锁定和补拍清单；自动语义 Provider、采用后编译 Timeline、生成缺口和真实综合验收继续开发。不能把本页保存当作已制作或交付视频。

## 用户流程与双端呈现

网页在已保存分镜下点击“匹配素材与补拍”；小程序分镜页有相同入口，未保存输入须先保存。两端均可只用本端选择项目视频/图片、填写整条或局部区间内容标注、调整逐镜头类型/方向/要求及排除标签、比较候选、查看素材、选择采用/保留原素材/补拍/暂留缺口、填写核对依据、锁定来源、保存新版本和查看来源历史。

默认不选择或采用任何候选。素材类型、可用时长和可靠方向满足条件，只说明这些条件可用。没有语义标注的主体、构图等仍显示待人工核对；登记时长与托管测量时长分开说明。用户须明确核对未验证条件，并填写采用依据，才能保存此类候选。用户标签或内容标注不能当作模型识别或质量测评。

已保存的补拍清单绑定精确分镜和素材决定版本，列明缺口镜头、目标时长、主体/动作/场景/构图/运镜/光影/风格、必须保留细节和已确认资料事实。网页提供文本导出，小程序可查看并主动复制清单；两者都不包含本机未保存选择。素材身份、标注或用途变化后须重新核对，不能沿用过期清单隐藏缺口。

## 共用需求与证据规则

`ShotRequirement` 是模板与分镜共同的校验模型。模板自动规划及原版本编辑候选共用类型、时长、方向、必需分析字段和标签条件；分镜适配器还提供目标时长、视觉描述、约束和用户确认事实。模板标签来自冻结的用户标签，不伪造缺失质量/语义分数。

明确排除项包括类型不符、源区间太短、超过模板源区间上限、已知方向不符、必需字段缺失、出现明确排除标签。仅供参考的视频和未核验上传不会进入候选。没有托管边界时可使用已登记的整条时长，但明确标为未测量、须人工确认；完全没有可用时长的视频不提供候选。图片按目标时长停留，源区间终点为空。

内容标注保存为 `user-shot-semantics/1` 的不可变版本，绑定素材身份和操作人，必须由用户确认。可有一条整片基础标注和互不重叠的局部标注；局部非空字段覆盖基础字段，标签合并。局部标注与已有镜头交集可作为候选区间，不宣称它是模型检测的切点。标注范围超出已知源时长或相互重叠时明确拒绝，不截断。

自然语言描述不同不等于内容相互矛盾。没有真实语义模型时，标准化后完全一致的描述可作为用户标注一致的依据；不同描述保留人工比较，不伪造同义理解或相似度百分比。产品事实和自由文字约束始终保留人工画面核对。真实托管语义/置信度和语义相似匹配仍待后续 Provider 接入，不能用手工标注替代它的验收。

候选排序优先支持证据更充分的项，再考虑相邻和已推荐来源，最后用稳定来源顺序决定。排序仅是建议，不自动写入采用记录。来源分组使用受管内容哈希/版本或稳定对象身份，重复登记同一对象不能绕过重复区间检查。重复使用同一图片或重叠视频区间须明确允许；不同区间仍保留来源关系。

## 版本与恢复

`0023_shot_matching` 只新增四张表，不改写既有 Job、账务或 Timeline：

| 数据 | 固定内容 |
| --- | --- |
| `asset_semantic_revisions` | 素材身份、用户标注版本、请求哈希和操作人 |
| `shot_match_reports` | 精确分镜版本、选定素材/分析/标注/用途快照、需求、候选区间和理由 |
| `storyboard_source_revisions` | 对每个镜头的采用/补拍/缺口决定、来源快照、核对依据、锁定与重复许可 |
| `storyboard_source_heads` | 当前素材决定版本指针 |

内容分镜版本与素材决定版本分别追加保存。来源锁定不能被新报告覆盖；改变需求后不能静默保留不适配的旧素材，删除锁定来源对应镜头也必须明确解锁。保存按文档及素材顺序加锁，检查旧版本基线和固定输入；旧基线冲突，不会覆盖其他页面的更新。同键同内容返回原结果，异内容同键冲突；原回执附当前版本指针，双端保留本机输入并提示核对新版本。

双端保存原操作路径、键和完整请求体，未知结果冻结新提交，先查回执，未查到后由用户重发原请求。缓存按账号/项目/分镜隔离，隐藏或上下文变化后忽略迟到写入；临时媒体播放地址只留在当前页面，隐藏时清除，不写入版本或持久缓存。素材播放使用已有网关的同租户对象签名，实际可用性取决于受管存储配置；本批合成元数据没有真实媒体，不作云播放证据。

## 接口与限制

统一 `/api/v1` 前缀，创建请求带 `Idempotency-Key`：

| 接口 | 用途 |
| --- | --- |
| `GET/POST /assets/{id}/semantics` | 当前内容标注 / 追加用户确认标注 |
| `GET /assets/{id}/semantic-revisions/{revision}` | 精确历史标注 |
| `GET /assets/{id}/semantic-requests/{key}` | 原标注保存回执 |
| `POST /assets/{id}/access` | 同租户图片/视频临时播放 |
| `GET/POST /storyboards/{id}/match-reports` | 分页摘要 / 固定输入候选报告 |
| `GET /storyboards/{id}/match-reports/{report}` | 报告详情及当前过期状态 |
| `GET /storyboards/{id}/match-requests/{key}` | 原匹配回执 |
| `GET/POST /storyboards/{id}/sourcing` | 当前来源 / 追加采用版本 |
| `GET /storyboards/{id}/source-revisions` | 分页来源历史 |
| `GET /storyboards/{id}/source-requests/{key}` | 原采用保存回执 |
| `GET /storyboards/{id}/reshoot-manifest` | 已保存版本的补拍文本与结构清单 |

每次明确选择1–100个项目素材，最多5000个来源区间；每个分镜最多500镜头，每镜头返回1–5个候选（双端默认3）。标注每素材最多500条，报告和版本快照最多2MiB。超限拒绝并要求显式缩小范围，不截断输入。列表分页，历史/详情另读。用户可清空素材选择后重新选择，恢复删除或变更素材造成的无效选择；已保存的来源锁定仍受保护。

跨端规则源 `web/shot-matching-form.js` 与 `miniprogram/src/vendor/shot-matching-form.js` 逐字一致；网页及原生页面各自处理网络/缓存。动态镜头 ID 的覆盖条件使用安全自有属性访问，不把特殊名称当作对象原型。
