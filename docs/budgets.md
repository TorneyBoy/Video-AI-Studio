# 租户用量与成本预算

平台只对托管 Provider 返回的 `usage`/`cost` 进行记账，不在控制面执行模型推理或媒体计算。金额以整数微单位保存，默认 1 USD = 1,000,000 微单位，避免浮点数参与预算比较。

## 配置预算

当前用户费用与恢复入口见本文末尾“C12个人费用工作台”。原空间预算配置仍为内部维护能力；个人项目上限不能提高空间额度。

```http
PUT /api/v1/tenants/{tenant_id}/budget
Content-Type: application/json

{
  "currency": "USD",
  "monthly_limit_micros": 50000000,
  "task_limit_micros": 5000000,
  "enforcement": "block",
  "enabled": true
}
```

`monthly_limit_micros` 是 UTC 自然月上限，`task_limit_micros` 是单个 Job 的上限。未配置预算的租户仍会记录 Provider 费用，但不会阻断任务。`GET /api/v1/tenants/{tenant_id}/budget` 返回当前自然月的已结算、预占和剩余额度；`GET /api/v1/billing/usage` 返回租户隔离的原始记账行。

## 提交与结算

生产提交先从服务端能力目录选择已验收的 Provider、模型和报价版本，再生成预占；直接素材分析、自动规划附带的分析以及渲染共用入口。客户端 `estimated_cost` 不能替换此数值。按请求计价预占服务端单次金额；按时长计价按能力强制时长上限预占，开始分钟取整，不能信任客户端上报较短时长。没有可计算的服务端价格或必要时长上限时拒绝生产提交。

开发/兼容路径仍可读取 Job payload 中的 `estimated_cost`（或 `provider_request.estimated_cost`），但这类客户端估算不构成未知费用结果的可信交付依据。估算超过月度或任务上限时，Job 会被创建为 `failed`，并带有 `policy_blocked=true`、`failure_code=budget_exceeded` 以及 `payload.budget` 审计信息。重复预占同一 Job 只返回既有账务行，不重复占额度。

Provider 轮询、分析/渲染结果和签名 Callback 共用结算函数。每个 Job 只有一条 `usage_ledger`；首次实际结算后金额和原始证据不可覆盖。重复结果按证据去重，后到不同金额进入 `usage_evidence` 待对账；只有内部操作显式批准后才产生 `usage_adjustments` 差额。结算超过预算时保留已发生的真实费用，并阻止正式交付。

缺少费用金额时记录 `pending_reconciliation` 与金额未知证据，保留已有预占；不把空费用对象视为免费。已取消任务的迟到费用照常记账，但不会恢复任务或创建可交付产物。未提交供应商的任务取消可释放预占，提交结果未知的任务继续保留预占等待对账。

云账单延迟时，只有已有正数、服务端能力报价生成的预占，且返回的 Provider/模型 ID/版本/币种与报价及提交快照一致、当前任务与月度额度再次校验通过，才能依据 `trusted_reservation_pending_bill` 完成业务交付。账务仍为 `pending_reconciliation`，`amount_micros` 字段此时代表保留的预占；审计中的实际金额保持 null，用量证据金额也为 null。没有可信预占、模型或币种不符、额度已收紧超限等情况继续暂停交付，并使用 `budget_cost_unknown`；不能把未知费用写成零或已结算。真实金额到达后才把该唯一账务行结算，重复及差额证据规则不变。这不是供应商费用硬上限，报价可能与后续账单不同。

旧分析路由漏做预占的恢复仅供内部维护：验证原远端作业、原请求哈希、源哈希和规范模型后，可带明确恢复原因补记缺失预占；仅允许没有结算金额且预占为 0 的待对账行，保留先前审计和不可变用量证据。不能通过普通用户 API 覆盖已结算行或已有可信预占。恢复保留原 Provider 请求/哈希，重试查询原作业，不重新提交云任务。

内部维护通过 `GET /api/v1/jobs/{job_id}/cost-evidence` 查看观察与调整，再使用 `POST /api/v1/jobs/{job_id}/reconcile-cost` 提交 `evidence_id` 和 `reason`。生产调用同时需要内部 API key 和签名租户身份，普通用户无权修改租户预算或批准费用调整。跨币种差额不自动换算。

PostgreSQL 按 Job、Workflow、Tenant、TenantBudget 的固定顺序锁定；即使租户暂未配置预算，也以租户行串行化费用。Tenant 使用 `FOR NO KEY UPDATE`，保留写入串行化，同时与新 Job 外键检查的 KEY SHARE 兼容；真实并发提交曾复现 FOR UPDATE 锁升级死锁，现有回归覆盖该场景。锁兼容关系见 [PostgreSQL 文档](https://www.postgresql.org/docs/16/explicit-locking.html#LOCKING-ROWS)。生产结构升级使用 `python -m app.cli migrate`，包含 `0007_usage_ledger_status`；历史 `002` SQL 文件只覆盖旧预算结构，不能作为当前版本的完整升级入口。


## C12个人费用工作台

网页“费用与恢复”和小程序billing页共用安全投影，不返回原始Provider响应、对象地址、认证信息或原始费用证据。项目总额统计整个项目周期；空间总额统计UTC月份。费用明细显示所选范围的全部历史，逐页加载；币种分开、不折算。settled为已记录结算，并不意味着已完成供应商正式账单核对；调整额及结算净额独立展示。pending_reconciliation保留估算，零保留且实际未知时显示“金额待核对”。新增接口所有`*_micros`响应字段为十进制字符串，避免JS浮点丢失微金额精度；条件保存的输入仍为校验后的安全整数。

`ProjectBudget`是空间预算之外的项目累计限制。所有者可通过`POST /projects/{id}/spending-limit`（兼容PUT）设置currency、limit_micros、base_revision。空值表示不增加项目上限，不等于提高空间月度/单任务限额。金额输入最多6位小数、非负，微金额至多9000000000000000；更新采用revision条件，不能静默覆盖他页设置。当前已结算/保留费用计入项目已用额，不能以降低上限释放；有其他币种的有效费用时不能用单币上限覆盖。修改和预占共用租户锁，结算仍记录真实超限费用并阻止后续未授权交付；迟到调整不会被丢弃。

固定输出报价使用`RenderQuote`，绑定时间线快照哈希、编辑版本、质量/格式/导出参数及服务/模型/报价版本，10分钟有效。创建报价不创建Job、不占费用；按已验收能力的最大允许时长估算预占，时长/画幅/格式超过服务声明时拒绝。普通视频和含额外效果的视频都必须在确认前选定带版本的价格。除开发header兼容模式外，新渲染必须携带quote_id和稳定操作键；确认、入队预占及首次外部提交分别核对输入/价格。报价只消费一次，原Job回执先于到期检查，因此断线后查到已提交任务不会再次生成。已知远端作业继续查询原身份，不因新价格而换任务。预占不是供应商最终费用保证，账单不同仍走现有不可覆盖结算和对账规则。

“恢复原任务”与“另建生成”明确分开。后者重新报价、使用新报价ID构造新逻辑键，保留旧Job和输出；不会自动变成强制重试。原生常规生成入口先按project/revision/quality查询已有Job，再查看输出或恢复；网页常规入口查看已有成片，另建入口单独展开。`GET /jobs`增加revision_id筛选，返回可信服务端绑定的任务。

取消/恢复使用`POST /billing/jobs/{id}/actions`，正文为action、expected_status、expected_attempt、expected_generation，必须带Idempotency-Key。Job锁下检查状态条件并写JobAction回执；同键原文重放只返回回执及当前状态，即使任务已再次失败也不重新恢复。未知结果通过`GET .../actions/{key}`先核对，之后仅沿用同键/原文；两端已阻止其他输入覆盖未确认提交。清除本地记录不取消服务器任务。取消不会被称为退款；已经待对账的行即使缺少旧远端记录也不释放。所有实际账务修订仍仅供内部维护。

自动检查覆盖真实PostgreSQL竞争、报价变化和过期、单次消费、首次外部执行的价格变化拦截及已知远端查询、原动作重放、项目上限和币种、微金额精度、断线/隐藏/账号变化。证据`data/testing/m2-billing/`。分析/规划附带分析的综合报价已接入（见下文）；仍需真实费用及微信设备验收，不能据此关闭整个C12或M2。


分析与规划综合报价（0014）：报价中的每个new子项按服务端价格预占，单任务限额逐项检查，项目累计/月度额度按分币种整批总额检查。cached或reused本次不新预占，也不表示历史任务免费。确认持有资产有序行锁和租户额度锁，先整批校验再插入全部Job/预占；后续任何失败一起回滚。不同报价同时确认同一组素材只创建一次分析；确认键不能用于两个报价。报价及读取回执都不调用供应商。已有结果、原任务依赖和源对象固定，首次收费调用前重核价格；已知远端查询不受新报价影响。取消/恢复仍按原任务的既有策略处理，未知费用预占不释放。本轮本机仅获取报价，未增加实际供应商费用或放宽测试配额。


批次计划报价（0015）对所有子项引用素材去重，只为真正新增分析计一次预占；每项分配金额用于解释整批总额，不重复结算。总额与项目/月度额度、逐分析任务上限在同事务中重核，成功后同时创建全部分析及计划/汇总Job；任一步失败整批回滚。汇总Job无独立媒体费用/执行身份。渲染仍按固定版本单独报价，D03整批渲染预算与取消/公平调度未完成；本轮只编译既有无媒体分析并演练一个模拟失败恢复，没有新增供应商请求或放宽云端测试配额。
